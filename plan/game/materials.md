# 素材採取・鍛冶システム設計（2026-10-06 実装済み：採取・売却・納品。鍛冶は次回）

## 位置づけ
- DQ1からの分岐点を意図的に作る。本作の差別化は「特性3択」＋「集める楽しみ」の二本柱とする
- 目的1：洞窟に反復訪問の理由を作る（現状は宝箱1回＋ボス1回で用済み）
- 目的2：戦闘以外の成長手段（金策・装備）を増やし、小ループを太らせる

## 採取ルール
- 洞窟マップに銅鉱脈タイル `O` を4箇所配置（扉の外3・扉の内1。座標案は後述）
- 鉱脈は通行不可。隣接マスでEキーを押すと採取できる（洞窟にNPCはいないためEキー競合なし）
- 複数隣接時は1箇所ずつ採取。採取済みは枯渇色になり「掘り尽くされた鉱脈だ」と表示
- 洞窟に入り直すたびに全復活。枯渇状態はscene-local（`this.mined`）で持ち、gameStateに入れない
- 収量は扉の外1〜2個、扉の内2〜3個（リスクと見合う逓増）

## 素材
- 第1弾：銅鉱石（copper）のみ
- 将来：鉄鉱石、銀、魔石を上位洞窟・高危険テリトリー用に拡張
- 所持は `player.mats = { copper: n }`。ステータス画面（Tキー）に表示、セーブ対象に含める

## 用途（Step1：採取＋売却＋納品＝実装済み）
- 鍛冶屋NPCを街道の村…ではなく坑道キャンプ (15,12) に配置し、買取（1個12G）を実装済み
- 親方への納品（銅3個→下層の鍵）が進行の要。採取が主目的に昇格した
- 戦闘金策（スライム5G前後）とのバランスは後述の収支試算を参照

## 用途（Step2：鍛冶クラフト）
- 新NPC「鍛冶屋」を街道の村 (14,7) に配置する（空きタイル確認済み）
- レシピ案：
  - 銅のつるぎ（ATK+3）＝ 銅3個
  - 銅のたて（守備+3）＝ 銅2個
- クラフト品は店売り品（どうのつるぎATK+2等）と競合しない強さにする
- UIは武器屋の在庫式（stock配列）を流用し、素材不足時は断り文を出す

## 収支試算（2026-10-06 検討）
- 1入坑の期待収量：外3箇所×1.5＋内1箇所×2.5＝約7個 → 12G換算で約84G
- 往復コスト：洞窟内遭遇率12%・敵Lv+2で20〜40歩＝2〜5戦。やくそう・宿20Gを差し引いても黒字
- てつのつるぎ120G＝約1.5入坑。試作の規模では速めだが、Lv上限10・単層洞窟の短さと釣り合う。重くしたければ買取10Gに下げる
- 放置稼ぎの心配なし：採取には歩行が必須で、歩けば遭遇する仕組みのため

## ヒント文案（発見可能性の担保）
- 洞窟入坑メッセージに追記：「光る岩は隣でEキーだ」
- 旅人(18,1)のセリフに1行追加：「洞窟の光る岩は 銅の鉱脈だ。隣でEキーを押せば掘れるぜ」
- Eキー自体は既存操作（はなす・送り）なので新規学習コストなし

## 見送った代替案
- 敵ドロップ化：戦闘偏重になり「非戦闘の成長手段」という目的が消えるため不採用
- フィールド採取：王命ゲートの外で序盤経済が崩れるためStep1では不採用（将来の高危険テリトリー用に保留）
- 採取ポイント制・耐久値：仕組みが重くなるため不採用。枯渇／復活の二値で十分

## 実装タスク分解
1. `dialogues.json`：洞窟マップに `O` を4箇所配置（外：(2,2)(12,5)(2,8)、内：(12,10)）＋鍛冶屋NPC追加、旅人ヒント＋入坑メッセージ追記
2. `state.js`：`player.mats = { copper: 0 }` のみ（枯渇はscene-local、買取は既存gold加算）
3. `DungeonScene.js`：Eキー採取（隣接走査）・枯渇表示・入坑リセット。`passable` に `O` を含めない
4. `FieldScene.js`：鍛冶屋の買取選択肢（売却→クラフトの連続選択は `t.choice` 連鎖で対応、Step2時に拡張）
5. `statusUi.js`：素材行（銅鉱石xN）を追加。セーブはplayer丸ごと保存のため自動対応
6. `worldbase.md`：洞窟凡例に `O` を追記
