# アドベンチャー式・4人パーティRPG 叩き台（2026-10-24）

> 提案：DQ1形式（1対1・マップ歩行）から離れ、
> 4人パーティ／マップ撤去／「進む」でイベント／斥候で事前情報／村⇄洞窟の往復／
> アセンション＋日数でやり込み、を中核にする。

---

## 1. 何が変わるか

| 項目 | 現状（DQ1形式） | 提案（アドベンチャー式） | 影響 |
|---|---|---|---|
| 戦闘 | 1対1・4コマンド | **4人 vs 敵群**・役割と対象選択 | 大（UI・数値・敵AI） |
| 移動 | 30x30マップ歩行 | **「進む」ボタンでノード移動** | 大（マップ描画を撤去） |
| 探索 | 空間の踏破 | **ルート選択＋斥候の情報** | 中（探索の意味が「情報」に移る） |
| 撤退 | マップを戻る | **いつでも撤退→前の村へ** | 中 |
| 成長 | 主人公1人の特性3択 | **4人分の成長＋役割** | 大（バランス4倍） |
| やり込み | 周回seed | **アセンション＋日数＋到達深度** | 中 |
| 端末 | PCキーボード前提 | **スマホ縦・大きなボタン** | 中（UI全面） |

**捨てるもの**：ワールドマップ、坑道マップ、歩行モーション、マップ用タイル/オブジェクト、1対1戦闘レイアウト。
**残せるもの**：敵40種＋図鑑、町・村・親方・王、銅/納品、特性（→パーティのパークへ転用）、BGM/効果音、デバッグ基盤。

---

## 2. コアループ

```
村（準備：編成・装備・斥候・依頼）
  ↓ 目的地を3択から選ぶ
道中ノード（戦闘／斥候イベント／宝／泉／分岐）
  ↓ 「進む」で次ノード。危険度が上がる
洞窟深部（ボス／大穴／帰還ポイント）
  ↓ 撤退するか、奥へ行くか
村へ帰還（戦利品を換金・納品・日数+1）
  ↓
次の遠征（アセンション段階が上がる）
```

- **1遠征＝1日**。日数は「遠征回数」であり、難度と報酬の物差し。
- 遠征中は**セーブ不可**（撤退か全滅で村へ）。スマホの短時間プレイと相性が良い。

## 3. パーティ設計（4人）

| 枠 | 役割 | 主な行動 |
|---|---|---|
| 前衛 | 盾・挑発・かばう | 防御、敵の対象を引く |
| 火力 | 単体/範囲攻撃 | 攻撃、会心、連撃 |
| 支援 | 回復・状態解除・強化 | 回復、解毒、バフ |
| 自由 | 4人目の選択枠 | 火力/支援/耐久のどれでも |

### 斥候は「役割」ではなく「情報と選択肢のレイヤー」

斥候を専用クラスにすると枠が1つ潰れて窮屈になるため、**パーティ全体の『斥候値』**として扱う。
村での upgrade（斥候の眼）と装備で上がり、**情報の深度**と**選べる行動**が増える。

| 斥候値 | 見える情報 | 増える選択肢 |
|---|---|---|
| 0 | 敵の数 | 戦う／撤退 |
| 1 | 敵の名前 | ＋迂回（戦わず次へ・日数コスト） |
| 2 | 構成（前衛/後衛・属性） | ＋待ち伏せ（先制1ラウンド） |
| 3 | 特性（硬い/毒/回復/反撃） | ＋弱点狙い（開幕ダメージ増） |
| 4 | 行動の傾向 | ＋交渉（一部の敵を回避／供物） |

- 情報は「判断材料」、選択肢は「リスクの取り方」。**斥候を上げる＝戦闘を避ける道具が増える**。
- 斥候値はレベルではなく**村の投資**で上がる（遠征の成果を還元する動線）。
- 斥候が高いほど「逃げる／避ける」が合理的になるため、評価は深度・持ち帰りで測る（第6節）。

---

## 4. 斥候と撤退（この案の核）

| 段階 | 見える情報 | 入手条件 |
|---|---|---|
| Lv0 | 敵の数だけ | 常に |
| Lv1 | 敵の名前 | 斥候1人 |
| Lv2 | 構成（前衛/後衛、属性） | 斥候Lv5＋装備 |
| Lv3 | 特性（硬い/毒/回復/反撃） | 斥候Lv10＋装備 |
| Lv4 | 次の行動の傾向 | 斥候Lv15＋スキル |

- **戦闘前**に「戦う／迂回／撤退」を選べる。斥候がいれば判断材料が増える。
- 戦闘中も**撤退**可能。代償は「荷物の一部＋日数消費」。ボスは不可を事前明示。
- 斥候が倒れると情報が失われる（情報は「生きた資源」）。

## 5. 戦闘（短く・群れ単位）

- 4人 vs 敵2〜4体。**1戦3〜5ラウンド**、1ラウンド10〜15秒を目標。
- コマンドは各キャラ2択＋全体1つ：`攻撃 / 技 / 防御`、全体は`撤退`。
- 対象選択は「敵をタップ」→「味方をタップ」（スマホ向け）。
- 敵の攻撃は**予告しない**が、斥候Lv4で傾向が見える（様式美としてのテルはここに統合）。
- 状態異常は2つまで。致死RNGは「テル／上限／回避」の条件を維持。

---

## 6. 評価軸（ここに矛盾がある）

提案の「**一度も逃げないのが最高**」は、**斥候と撤退を核にする設計と正面から衝突**します。

| 問題 | 内容 |
|---|---|
| 逆インセンティブ | 逃げるのが賢い場面でも「評価のため」に突っ込む＝斥候の意味が消える |
| RNG死と同じ構図 | 「死なない」を評価したら安全策が最適解になったのと同じ。今回は「逃げない」が無謀を強制する |
| 初心者に厳しい | 情報が少ない序盤ほど逃げたい。そこで減点される |

**推奨する評価軸：**

| 軸 | 定義 | 備考 |
|---|---|---|
| 到達深度 | その遠征でどこまで行ったか | 逃げても価値が残る |
| 持ち帰り | 銅・魔石・宝の換金額 | 撤退の合理性を担保 |
| 日数 | 遠征回数（少ないほど高効率） | **上限として使う**（締切）。スコアに直接足さない |
| 発見 | 初回の敵・地形・話 | 逃げても発見は残る |
| （任意）誓約 | 「逃げずに最深到達」など | **バッジ／称号のみ**。メイン評価にしない |

- 「逃げない」は**プレイヤーが自分で選ぶ縛り**として残す。評価の土台にしない。
- 日数は「同じ日数でより深く」が競技性を持つ。日数そのものを増やすほど得、にはしない（周回作業になる）。

## 9. リスク

| リスク | 兆候 | 対策 |
|---|---|---|
| 規模の爆発 | V3で工数が倍 | 役割を4固定、技は各3つまで |
| 4人バランス | 1人が常に最適解 | 敵の範囲攻撃・役割特効で全員に役割 |
| 探索の喪失 | 「進む」連打になる | ノード選択に情報とリスクを必ず添える |
| スマホUIの後付け | 文字が読めない | V0から縦960x540想定で作る |
| 既存コードの混乱 | 2つの戦闘が混在 | 旧戦闘は残し、新モードを別シーンで追加（比較可能に） |
| 逃げない評価の矛盾 | 無謀プレイが最適化 | 評価軸を深度・持ち帰りに。逃げないは称号のみ |
| 日数の作業化 | 周回が義務に | 日数は上限（締切）として使い、報酬に直結させない |

## 11. 実装方針：リファクタではなく「0ベース＋資産再利用」

### 判断材料（現状のコード）

| 区分 | 行数 | 新作で使うか |
|---|---|---|
| `FieldScene` + `TownScene` + `DungeonScene` + `BattleScene` | 約2,232行 | **使わない**（マップ歩行・1対1戦闘） |
| `actors` / `tileArt` / `fieldMap` / `regions` / `charArt` | 約387行 | ほぼ使わない（歩行・タイル） |
| `enemies.js` / `traits.js` | 203行 | **使う**（敵40種・特性） |
| `enemyArt.js` / `sound.js` / `debug.js` | 424行 | 使う（改修して流用） |
| `state.js`（セーブ・seed） | 229行 | **考え方だけ流用**（構造は作り直す） |
| 画像 | 121枚 / 156MB | **そのまま使う**（敵・町・背景） |

**結論：ゲームロジックは0ベース。データと素材は引き継ぐ。**
リファクタは「消す予定の2,200行を直しながら作り替える」ことになり、二重の手間になる。

### 推奨構成

```
src/
  next/                 ← 新作（この中だけで完結）
    core/               純JS・DOM非依存（テスト可能）
      battle.js         4人vs敵群の解決
      expedition.js     ノード進行・日数・撤退
      scout.js          斥候値と情報開示
      party.js          4人の成長・装備
    ui/                 DOM/CSS（スマホ縦）
      screen-village.js
      screen-node.js
      screen-battle.js
    data/               enemies/traits を next 用に薄く包む
  legacy/               ← 旧DQ1（触らない・参照用）
```

- **エンジン**：ノード式＋スマホUIなら **DOM/CSS** が最短。Phaserはキャンバス拡大・文字・タップUIで不利。
  戦闘の敵絵は `<img>` で表示できるため、Phaser依存を外せる。
- **旧作は消さない**：`legacy/` か別ブランチに退避し、新作と比較できる状態を保つ。
- **データはコピーではなく参照**：`enemies.js` はそのまま import し、新作側で必要なら wrapper を噛ませる。

### 移行手順

| 順 | 内容 | 目安 |
|---|---|---|
| 1 | 新エントリ `next.html` と `src/next/` の空殻（画面遷移だけ） | 2h |
| 2 | `core/battle.js` を純JSで実装＋Nodeで簡易シミュレーション | 8〜12h |
| 3 | `screen-battle` をDOMで描画（4人・敵3体・コマンド） | 8〜12h |
| 4 | `screen-node` の「進む／迂回／撤退」と斥候情報 | 6〜8h |
| 5 | `screen-village`（編成・投資・出発） | 6〜8h |
| 6 | 縦切り1周（村→5ノード→帰還） | 4h |

**合計 34〜46h** で「触れる縦切り」。既存コードの改修は含めない。
